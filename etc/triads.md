# Промежуточное представление (последовательность триад) для test.c

Триады сгенерированы вручную в точности по алгоритму обхода AST, реализованному
в `semantic.cxx` (функции `visitProgram`, `visitFuncDecl`, `visitBlock`,
`visitStmt`, `visitVarDecl`, `visitAssign`, `visitIf`, `visitFor`, `visitWhile`,
`visitReturn`, `visitCallExpr`, `visitBinOp`, `visitPostfixInc`).

Формат: `N: ОПЕРАЦИЯ(операнд1, операнд2)`. Ссылка на результат триады с номером
`N` обозначается `^N`. Метки переходов (`?`) заполняются после генерации всего
охватывающего блока — итоговые значения уже подставлены ниже.

## Прототип функции `calculate` (строка 6)

Для прототипа параметры регистрируются в таблице символов, но триады `PARAM`
не генерируются — это особенность реализации (`if (!isProto) addTriad(...)`).

```
1: FUNC_BEGIN(calculate, int)
2: FUNC_END(calculate)
```

### `int x = 10;` (строка 10)

### `int y = 20;` (строка 11)

```
5: :=(y, 20)
```

### `int result = 0;` (строка 12)

```
6: :=(result, 0)
```

### `result = x + y * 2;` (строка 15)

Сначала вычисляется `y * 2`, затем `x + ^7`, затем результат присваивается `result`
(порядок соответствует обходу `visitBinOp`: левый операнд обходится раньше правого).

```
7: *(y, 2)
8: +(x, ^7)
9: :=(result, ^8)
```

### `if (x > 5 && y < 100) {...} else {...}` (строки 18–22)

Условие `x > 5 && y < 100` раскладывается на две триады сравнения и одну триаду
логического `&&`. Триада `IF` — это условный переход «выполнить THEN, иначе
перейти по второму операнду» в терминах данной реализации (`IF(cond, label_else)`).
После THEN-блока следует безусловный `JUMP` за пределы `if-else`.

```
10: >(x, 5)
11: <(y, 100)
12: &&(^10, ^11)
13: IF(^12, ^17)
14: +(result, 1)
15: :=(result, ^14)
16: JUMP(^19)
17: -(result, 1)
18: :=(result, ^17)
```

Пояснение к меткам: `13: IF(^12, ^17)` означает «если `^12` ложно — перейти на
триаду 17 (начало `else`)»; `16: JUMP(^19)` означает «после выполнения `then`
безусловно перейти на триаду 19 (первая инструкция после всего `if-else`)».

### `for (int i = 0; i < 5; i++) { result = result + i; }` (строки 25–27)

Инициализация цикла генерируется как обычное присваивание; после неё фиксируется
точка возврата цикла (`loopStart = 20`); пост-инкремент (`i++`) физически
генерируется в коде уже после тела цикла, хотя в исходном тексте записан в
заголовке `for` — таков порядок обхода в `visitFor`.

```
19: :=(i, 0)
20: <(i, 5)
21: IF_FALSE(^20, ^26)
22: +(result, i)
23: :=(result, ^22)
24: ++(i)
25: JUMP(^20)
```

Пояснение: `21: IF_FALSE(^20, ^26)` — если условие `^20` ложно, перейти на
триаду 26 (выход из цикла); `25: JUMP(^20)` — безусловный переход обратно к
проверке условия (триада 20).

### `int counter = 0;` (строка 30)

```
26: :=(counter, 0)
```

### `while (counter < 3) { counter++; }` (строки 31–33)

```
27: <(counter, 3)
28: IF_FALSE(^27, ^31)
29: ++(counter)
30: JUMP(^27)
```

Пояснение: `28: IF_FALSE(^27, ^31)` — выход из цикла на триаду 31, если условие
ложно; `30: JUMP(^27)` — переход обратно к проверке условия.

### `result = calculate(x, y);` (строка 36)

Аргументы вызова передаются триадами `ARG` в порядке их следования, затем
генерируется сама триада вызова с указанием количества аргументов.

```
31: ARG(x)
32: ARG(y)
33: CALL(calculate, 2)
34: :=(result, ^33)
```

### `printf("Result: %d\n", result);` (строка 38)

Вызов как самостоятельный оператор (`visitCallStmt`) — результат вызова не
присваивается переменной, но триада `CALL` всё равно формируется.

```
35: ARG("Result: %d\n")
36: ARG(result)
37: CALL(printf, 2)
```

### `return 0;` (строка 39)

```
38: RETURN(0)
```

### Конец функции `main`

```
39: FUNC_END(main)
```

## Определение функции `calculate` (строки 43–45)

В отличие от прототипа, при разборе полного определения для каждого параметра
генерируется триада `PARAM` (повторная регистрация в таблице символов
игнорируется как неошибочная).

```
40: FUNC_BEGIN(calculate, int)
41: PARAM(a, int)
42: PARAM(b, int)
43: +(a, b)
44: RETURN(^43)
45: FUNC_END(calculate)
```
